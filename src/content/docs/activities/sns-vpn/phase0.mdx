### Étape 0.2 : Création des VMs pour l'Étudiant X (Client VPN)

#### 🔧 Tâche : Importer et configurer la VM Client VPN (XUbuntu)

**1. Importer l'image OVA**

- Télécharger (si ce n'est pas déjà fait) l'image de la VM XUbuntu via Torrent
- Dans VirtualBox : `Fichier` → `Importer un appareil virtuel`
- Sélectionner le fichier `.ova`
- **Avant d'importer**, modifier le nom : `VPN-Client-X` (remplacer X par votre numéro)
- Importer

**2. Configuration réseau de la VM**

Avant de démarrer la VM, configurez les paramètres réseau :

- Sélectionner la VM → `Configuration` → `Réseau`
- **Adapter 1** :
  - ✅ Activé
  - Mode d'accès réseau : `Accès par pont`
  - Nom : Sélectionner votre interface réseau physique (généralement `eno1` ou `eth0`)
  - Type de carte : `Paravirtualized Network (virtio-net)`
  - **⚠️ Régénérer l'adresse MAC** : Cliquer sur l'icône de rafraîchissement
- Adapters 2, 3, 4 : Désactivés

**3. Configurer l'IP fixe du Client VPN**

Démarrer la VM et se connecter.

Configurer l'adresse IP fixe de la VM en utilisant la méthode de votre choix (interface graphique ou terminal).

**4. Vérification**
```bash
ip a                          # Vérifier l'IP : 172.25.X.10/16
ip route                      # Vérifier la route par défaut
ping -c 4 172.25.254.254      # Ping gateway LABO
ping -c 4 8.8.8.8             # Ping Internet
```

:::tip[Validation Client VPN]
✅ Vous devez obtenir :
- IP : 172.25.X.10/16
- Gateway : 172.25.254.254
- Ping gateway : OK
- Ping Internet : OK
:::

#### 🔧 Tâche : Importer et configurer la VM SNS EVA1 (Étudiant X)

**Contexte :** La VM SNS EVA1 de Stormshield Academy est livrée avec un client graphique et un serveur pré-configurés pour le contexte de la Stormshield Academy. Nous devons adapter cette configuration pour notre activité VPN.

**1. Importer l'image OVA du pack EVA1**

- Télécharger EVA1 via Torrent (si ce n'est pas déjà fait)
- Importer le **SNS (pare-feu)** : renommer en `SNS-Client-X`


**2. Configuration de la VM SNS**

- Sélectionner `SNS-Client-X` → `Configuration`
- **Système** : Augmenter si possible
  - RAM : 2048 MB minimum
  - Processeur : 2 CPU

- **Réseau** :
  - **Adapter 1** (Interface OUT - vers LABO/Internet) :
    - ✅ Activé
    - Mode : `Accès par pont`
    - **⚠️ Régénérer l'adresse MAC**

  - **Adapter 2** (Interface IN - vers réseau interne) :
    - ✅ Activé
    - Mode : `Réseau interne`
    - Nom : `reseau-interne-X` (⚠️ Remplacer X par votre numéro)
    - **⚠️ Régénérer l'adresse MAC**

  - Adapters 3 et 4 : Désactivés

**3. Reconfiguration des interfaces réseau du SNS**

Une fois connecté à l'interface web du SNS :

**Étape 1 : Configurer l'interface OUT**
- Sélectionner l'interface OUT (généralement `eth0`)
- Type : `Statique`
- Adresse IP : `172.25.X.254`
- Masque : `255.255.0.0` (ou `/16`)
- Gateway : `172.25.254.254`
- DNS : `172.25.254.15`

**Étape 2 : Configurer l'interface IN**
- Sélectionner l'interface IN (généralement `eth1`)
- Type : `Statique`
- Adresse IP : `10.X.0.254`
- Masque : `255.255.255.0` (ou `/24`)
- Gateway : laisser vide

**4. Vérification de la nouvelle configuration**

**Depuis votre machine hôte physique :**
```bash
ping 172.25.X.254     # Doit répondre
```

**Accéder à la nouvelle interface web :**
- URL : `https://172.25.X.254/admin`

**Depuis l'interface web du SNS, ouvrir une console CLI :**
- Menu : `SYSTÈME` → `Console CLI`
- Tester :
```bash
SYSTEM PING host=172.25.254.254   # Gateway LABO
SYSTEM PING host=8.8.8.88.8.8.8          # Internet
```

**Depuis votre VM Client XUbuntu :**
```bash
ping 172.25.X.254     # Interface OUT du SNS
```

:::tip[Validation SNS Client]
✅ Tous les pings doivent fonctionner
✅ Vous pouvez accéder à l'interface web : `https://172.25.X.254/admin` depuis votre machine hôte ou la VM Client
✅ Le client graphique n'est plus nécessaire, vous pouvez l'arrêter (mais le conserver pour un usage futur)
:::

:::caution[Régénération des adresses MAC]
⚠️ **Très important** : Pensez à régénérer les adresses MAC de toutes vos VMs pour éviter les conflits réseau avec d'autres étudiants utilisant les mêmes images OVA.
:::

### Étape 0.3 : Création des VMs pour l'Étudiant Y (Serveur VPN)

#### 🔧 Tâche : Importer et configurer la VM SNS EVA1 (Serveur VPN principal)

**⚠️ Cette VM est la plus importante de l'activité : c'est elle qui hébergera le serveur VPN SSL.**

**1. Importer l'image OVA du pack EVA1**

- Importer les VMs suivantes :
  - Le **SNS (pare-feu)** : renommer en `SNS-Serveur-Y`

**2. Configuration de la VM SNS**

- Sélectionner `SNS-Serveur-Y` → `Configuration`
- **Système** : Augmenter si possible
  - RAM : 2048 MB minimum
  - Processeur : 2 CPU

- **Réseau** :
  - **Adapter 1** (OUT - Interface publique VPN) :
    - ✅ Activé
    - Mode : `Accès par pont`
    - Nom : Votre interface physique
    - **⚠️ Régénérer l'adresse MAC**
    - **Cette interface recevra les connexions VPN SSL**

  - **Adapter 2** (IN - Réseau entreprise) :
    - ✅ Activé
    - Mode : `Réseau interne`
    - Nom : `reseau-interne-Y` (⚠️ Remplacer Y par votre numéro)
    - **⚠️ Régénérer l'adresse MAC**

  - Adapters 3 et 4 : Désactivés


**3. Reconfiguration des interfaces réseau**

**Configurer l'interface OUT :**
- Adresse IP : `172.25.Y.254`
- Masque : `255.255.0.0` (ou `/16`)
- Gateway : `172.25.254.254`
- DNS : `172.25.254.15`

**Configurer l'interface IN :**
- Adresse IP : `10.Y.1.254`
- Masque : `255.255.255.0` (ou `/24`)
- Gateway : laisser vide

**Appliquer et redémarrer les services réseau**

**4. Vérification**

Depuis votre machine hôte :
```bash
ping 172.25.Y.254
```

Accéder à l'interface web : `https://172.25.Y.254/admin`

Depuis la console système du SNS :
```bash
ping 172.25.254.254
ping 8.8.8.8
```

:::tip[Validation SNS Serveur]
✅ Les pings doivent réussir
✅ Interface web accessible : `https://172.25.Y.254/admin`
✅ C'est sur cette interface OUT que le serveur VPN écoutera (port 443)
:::

#### 🔧 Tâche : Importer et configurer la VM Serveur Debian (Ressources entreprise)

**1. Importer l'image OVA**

- Télécharger l'image `.ova` de Debian via Torrent
- Importer dans VirtualBox
- Renommer : `Serveur-Debian-Y`

**2. Configurer la VM**

- **Réseau** :
  - Adapter 1 : ✅ Activé
  - Mode : `Réseau interne`
  - Nom : `reseau-interne-Y` (⚠️ Même nom que l'interface IN du SNS)
  - **⚠️ Régénérer l'adresse MAC**

**3. Connexion et configuration IP**

Démarrer la VM et se connecter :
- Login : `sysadmin`
- Mot de passe : `netlab123`

**Configurer l'IP fixe :**

Utiliser la méthode de votre choix pour configurer :
- Adresse IP : `10.Y.1.20/24`
- Gateway : `10.Y.1.254`
- DNS : `172.25.254.15`

**4. Installation d'Apache2**

Instructions :
1. Installer Docker si ce n'est pas déjà fait
2. Cloner le dépôt https://github.com/manastria/docker-http-test
3. Lancer le serveur avec `docker compose up -d`


**5. Vérification**
```bash
ping 10.Y.1.254          # Ping vers le SNS IN
ping 172.25.254.254      # Ping vers la gateway LABO (doit passer via le SNS)
curl http://localhost    # Affiche la page web
```

:::tip[Validation Serveur Debian]
✅ Ping vers le SNS : OK
✅ Ping vers la gateway LABO : OK
✅ Page web accessible en local : OK
:::

### Étape 0.4 : Validation globale de la Phase 0

#### Tests de connectivité à effectuer

Complétez le tableau suivant dans votre compte-rendu :

| Source         | Destination     | Commande              | Résultat attendu   | ✅/❌ |
| -------------- | --------------- | --------------------- | ------------------ | ----- |
| Client VPN (X) | Gateway LABO    | `ping 172.25.254.254` | OK                 |       |
| Client VPN (X) | SNS Client OUT  | `ping 172.25.X.254`   | OK                 |       |
| Client VPN (X) | SNS Serveur OUT | `ping 172.25.Y.254`   | OK                 |       |
| Client VPN (X) | Serveur Debian  | `ping 10.Y.1.20`      | **ÉCHEC** (normal) |       |
| SNS Serveur    | Gateway LABO    | `ping 172.25.254.254` | OK                 |       |
| SNS Serveur    | Internet        | `ping 8.8.8.8`        | OK                 |       |
| Serveur Debian | SNS IN          | `ping 10.Y.1.254`     | OK                 |       |
| Serveur Debian | Gateway LABO    | `ping 172.25.254.254` | OK                 |       |

:::caution[Point important]
⚠️ Il est **NORMAL** que le Client VPN ne puisse pas pinguer le Serveur Debian (10.Y.1.20).
**C'est justement le problème que le VPN va résoudre !**

Le Client est sur le réseau 172.25.0.0/16 (Internet simulé).
Le Serveur est sur le réseau 10.Y.1.0/24 (réseau privé entreprise).
Sans VPN, ils ne peuvent pas communiquer.
:::
