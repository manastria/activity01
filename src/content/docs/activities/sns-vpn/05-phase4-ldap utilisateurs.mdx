## Contexte : Pourquoi un annuaire *LDAP* ?

### Le besoin métier

Avant d'ouvrir un tunnel VPN, le pare-feu doit **vérifier l'identité** de l'utilisateur qui se connecte. Pour **TechServices SARL**, cela signifie :

- Les collaborateurs de l'agence de Lyon s'authentifient avec leur login/mot de passe
- Seuls les utilisateurs autorisés peuvent établir un tunnel VPN
- L'administrateur peut révoquer un accès en désactivant un compte

### *LDAP* en bref

*LDAP* (*Lightweight Directory Access Protocol* — Protocole léger d'accès aux annuaires) est le protocole standard pour stocker et interroger des informations sur les utilisateurs. Le Stormshield SNS intègre un **annuaire LDAP interne** : pas besoin de serveur supplémentaire, tout est géré directement dans le pare-feu.

:::tip[En production]
Dans une vraie entreprise, le SNS se connecterait à l'*Active Directory* (*AD*) existant pour centraliser la gestion des utilisateurs. L'annuaire interne est idéal pour une PME ou un environnement de test comme celui-ci.
:::

:::caution[Rôle spécifique]
**Cette phase est réalisée par l'Étudiant Y uniquement** (Serveur VPN).
L'Étudiant X peut observer et prendre des notes sur la structure LDAP.
:::

## Étape 4.1 : Activation de l'annuaire LDAP interne

<Steps>

1. **Accéder à la configuration de l'annuaire**

   `Configuration` → `Utilisateurs` → `Configuration des annuaires`

2. **Activer l'annuaire LDAP interne**

   Onglet **Annuaire interne** :

   | Paramètre                       | Signification                                                                     | Valeur       |
   | ------------------------------- | --------------------------------------------------------------------------------- | ------------ |
   | Activer l'annuaire LDAP interne |                                                                                   | ✅ Cocher    |
   | Organisation                    | Le nom de l’organisation (nom domaine)                                            | techservices |
   | Domaine                         | Le TLD (_Top Level Domain_) du domaine.                                           | `local`      |
   | Mot de passe                    | Un mot de passe permettant de se connecter à l’annuaire LDAP                      |              |
   | Haché du mot de passe           | algorithme de hachage utilisé pour enregistrer les mots de passe des utilisateurs |              |

   - **Activer le profil d'authentification 0 (interne) sur l'interface sélectionnée** : **out**

   L’étape suivante permet de configurer des paramètres complémentaires :
   - **Activer le profil d’authentification 0 (_internal_) sur une interface** : Dans le cas où le profil n’a pas déjà été activé. Si c’est le cas, cette option sera désactivée (grisée) et un message indique que l’association entre profil d’authentification et interface est déjà réalisée.
   - **Activer l'enrôlement des utilisateurs via le profil 0 (interne) du portail Web** : Active le service d’enrôlement sur le profil 0 (interne) permettant aux utilisateurs de remplir un formulaire de création de compte qui sera soumis à l’approbation de l’administrateur.
   - **Autoriser l’accès à la base LDAP** : Donne la possibilité d’exposer le service LDAP sur le réseau et d’y accéder depuis un client LDAP. Si cet accès n’est pas nécessaire, il est vivement conseillé de ne pas activer cette option.

3. **Appliquer la configuration**

   Cliquer sur `Appliquer`.

</Steps>

## Étape 4.2 : Création de la structure organisationnelle

Une *OU* (*Organizational Unit* — Unité organisationnelle) est un conteneur qui permet d'organiser les objets de l'annuaire (utilisateurs, groupes) en sous-dossiers logiques.

Vous allez créer deux *OU* sous la racine `dc=techservices,dc=local` :

```
dc=techservices,dc=local
  ├── ou=utilisateurs_vpn   ← contiendra les comptes utilisateurs
  └── ou=groupes            ← contiendra les groupes d'accès
```

<Steps>

1. **Accéder à la gestion de l'annuaire**

   `Configuration` → `Utilisateurs` → `Annuaire` → onglet **Gestion de l'annuaire**

2. **Créer l'OU « utilisateurs_vpn »**

   - Clic droit sur `dc=techservices,dc=local`
   - `Ajouter une unité organisationnelle`
   - **Nom** : `utilisateurs_vpn`
   - **Description** : `Utilisateurs autorisés à se connecter au VPN SSL`
   - Cliquer sur `Créer`

3. **Créer l'OU « groupes »**

   - Clic droit sur `dc=techservices,dc=local`
   - `Ajouter une unité organisationnelle`
   - **Nom** : `groupes`
   - **Description** : `Groupes d'utilisateurs`
   - Cliquer sur `Créer`

</Steps>

:::tip[Compte-rendu]
📝 **À ajouter dans votre compte-rendu (Section 5.2) :**
- Capture d'écran de l'arborescence LDAP avec les deux OU créées
:::

## Étape 4.4 : Création du groupe d'utilisateurs VPN

### 🎯 Pourquoi un groupe ?

En Phase 5, vous associerez les utilisateurs autorisés au VPN SSL. Plutôt que d'ajouter les utilisateurs **un par un**, on autorise un **groupe entier** : plus simple à gérer et à faire évoluer.

### 🔧 Tâche : Créer le groupe « Utilisateurs_VPN »

<Steps>

1. **Créer le groupe**

   - Clic droit sur `ou=groupes` → `Ajouter un groupe`

   | Paramètre              | Valeur                                                        |
   | ---------------------- | ------------------------------------------------------------- |
   | **Nom du groupe (CN)** | `Utilisateurs_VPN`                                            |
   | **Description**        | `Groupe des utilisateurs autorisés à se connecter au VPN SSL` |

2. **Ajouter les membres**

   Onglet **Membres** → `Ajouter` :
   - ✅ `Jean Dupont (jdupont)`
   - ✅ `Marie Martin (mmartin)`
   - ✅ `Pierre Durand (pdurand)`

3. **Créer le groupe**

   Cliquer sur `Créer`.

</Steps>

Arborescence finale :

```
dc=techservices,dc=local
  ├── ou=utilisateurs_vpn
  │     ├── cn=Jean Dupont (jdupont)
  │     ├── cn=Marie Martin (mmartin)
  │     └── cn=Pierre Durand (pdurand)
  └── ou=groupes
        └── cn=Utilisateurs_VPN (3 membres)
```

## Étape 4.5 : Validation de l'annuaire LDAP

### 🔧 Tâche : Tester l'authentification

Le SNS dispose d'un outil de diagnostic intégré pour vérifier qu'un utilisateur peut bien s'authentifier.

`Configuration` → `Utilisateurs` → `Annuaire` → onglet **Test d'authentification**

**Tests à effectuer :**

| Utilisateur | Mot de passe        | Résultat attendu            |
| ----------- | ------------------- | --------------------------- |
| `jdupont`   | `Vpn2025!`          | ✅ Authentification réussie |
| `mmartin`   | `Vpn2025!`          | ✅ Authentification réussie |
| `pdurand`   | `Vpn2025!`          | ✅ Authentification réussie |
| `jdupont`   | `MauvaisMotDePasse` | ❌ Échec (attendu)          |

Pour chaque test réussi, vérifiez que la réponse indique bien :
- Le *DN* complet de l'utilisateur : `cn=Jean Dupont,ou=utilisateurs_vpn,dc=techservices,dc=local`
- Son appartenance au groupe : `cn=Utilisateurs_VPN,ou=groupes,dc=techservices,dc=local`
