## Contexte : Pourquoi un annuaire *LDAP* ?

Avant d'ouvrir un tunnel VPN, le pare-feu doit **vérifier l'identité** de l'utilisateur qui se connecte. Pour **TechServices SARL**, cela signifie :

- Les collaborateurs s'authentifient avec leur login/mot de passe
- Seuls les utilisateurs autorisés peuvent établir un tunnel VPN
- L'administrateur peut révoquer un accès en désactivant un compte

*LDAP* (*Lightweight Directory Access Protocol* — Protocole léger d'accès aux annuaires) est le protocole standard pour stocker et interroger des informations sur les utilisateurs. Le SNS intègre un **annuaire LDAP interne** : pas besoin de serveur supplémentaire, tout est géré directement dans le pare-feu.

:::tip[En production]
Dans une vraie entreprise, le SNS se connecterait à l'*Active Directory* (*AD*) existant pour centraliser la gestion des utilisateurs. L'annuaire interne est idéal pour une PME ou un environnement de test comme celui-ci.
:::

## Étape 4.1 : Activation de l'annuaire LDAP interne

<Steps>

1. **Accéder à la configuration des annuaires**

   `Configuration` → `Utilisateurs` → `Configuration des annuaires`

   Cliquer sur **Création d'un annuaire LDAP interne** puis `Suivant`.

2. **Renseigner les paramètres de l'annuaire**

   | Paramètre | Signification | Valeur |
   |-----------|---------------|--------|
   | **Organisation** | Nom de domaine de l'organisation | `techservices` |
   | **Domaine** | *TLD* (*Top Level Domain*) | `local` |
   | **Mot de passe** | Mot de passe d'accès à l'annuaire LDAP | `netlab123` |
   | **Haché du mot de passe** | Algorithme de hachage des mots de passe utilisateurs | (laisser par défaut) |

   Cliquer sur `Suivant`.

3. **Associer le profil d'authentification à l'interface**

   - Sélectionner l'interface **`out`** pour le profil 0
   - Cliquer sur `Terminer`

   Un résumé de la configuration s'affiche confirmant la création de l'annuaire.

</Steps>

📝 **À ajouter dans votre compte-rendu (Section 5.1) :**
- Capture d'écran du résumé de configuration affiché après la création de l'annuaire
:::

## Étape 4.3 : Création du groupe d'utilisateurs VPN

### 🎯 Pourquoi un groupe ?

Plutôt que d'attribuer des droits d'accès VPN utilisateur par utilisateur, on autorise un **groupe entier** : plus simple à gérer et à faire évoluer (ajouter un utilisateur = l'ajouter au groupe).

### 🔧 Tâche : Créer le groupe « VPN »

<Steps>

1. **Créer le groupe**

   Toujours dans `Configuration` → `Utilisateurs` → `Utilisateurs` :

   Cliquer sur `Ajouter un groupe` :
   - **Nom du groupe** : `VPN`

2. **Ajouter les membres au groupe**

   Dans la fiche du groupe, cliquer sur `+Ajouter` et rechercher chaque utilisateur par son *CN* (*Common Name*), le _drag and drop_ est aussi possible :
   - ✅ `jdupont`
   - ✅ `mmartin`
   - ✅ `pdurand`

   :::caution[Recherche par CN obligatoire]
   Recherchez les utilisateurs dans le champ **Cn** — sinon le SNS affichera un message d'erreur lors de la création du groupe.
   :::

3. **Sauvegarder le groupe**

   Cliquer sur `Appliquer` puis `Sauvegarder`.

</Steps>

:::tip[Compte-rendu]
📝 **À ajouter dans votre compte-rendu (Section 5.3) :**
- Capture d'écran de la fiche du groupe `VPN` montrant ses 3 membres

## Étape 4.4 : Attribution des droits d'accès VPN SSL

Il ne suffit pas de créer un groupe : il faut **explicitement autoriser** ce groupe à utiliser le service VPN SSL via la politique des droits d'accès.

<Steps>

1. **Accéder aux droits d'accès**

   `Configuration` → `Utilisateurs` → `Droits d'accès`

2. **Sélectionner l'onglet « Accès détaillé »**

3. **Ajouter le groupe VPN**

   Cliquer sur `+Ajouter` et sélectionner le groupe `VPN`.

4. **Autoriser l'accès VPN SSL**

   Sur la ligne du groupe `VPN` :
   - Colonne **VPN SSL** : sélectionner `Autoriser`
   - Double-cliquer sur la colonne **État** pour passer la règle à `Activé`

5. **Appliquer et sauvegarder**

   Cliquer sur `Appliquer` puis `Sauvegarder`.

</Steps>

:::note[Rôle de cette étape]
Cette configuration est **indépendante** des règles de filtrage que vous créerez en Phase 6. Elle définit les **droits applicatifs** : qui a le droit d'utiliser le service VPN SSL. Le filtrage réseau contrôle, lui, les flux autorisés à traverser le pare-feu.
:::

:::tip[Compte-rendu]
📝 **À ajouter dans votre compte-rendu (Section 5.4) :**
- Capture d'écran de la page des droits d'accès montrant le groupe `VPN` avec l'accès VPN SSL autorisé et activé
